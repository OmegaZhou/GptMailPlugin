# 原插件入口审计（2026-10-11）

当前实际状态：原插件 0.5.2 已安装且引用的邮箱应用已连接；原插件详情主按钮为“在聊天中试用”，关联邮箱应用详情主按钮为“打开插件”。后者已实际打开内嵌面板并通过服务测试及刷新恢复。

## 新证据

- 浏览器实际加载的原插件详情响应包含一个正确的 `release.app_ids` / `app_manifest` 依赖，但顶层 `canonical_app_id` 为 null。
- 已加载的插件详情页面代码从已安装插件记录读取 `canonicalAppId`，再检查该应用的全局入口；不是遍历 `app_ids` 并把唯一依赖自动作为主应用。
- 页面按钮组件仅在提供 `onOpenPlugin` 时渲染“打开插件”。原插件未获得该回调，退回“在聊天中试用”。
- “编辑插件”菜单实际跳转到预填 Plugin Creator 的聊天输入框，不提供主应用关联编辑表单。没有发送该预填消息。
- 官方插件包文档允许 `.app.json` 声明注册应用依赖；未找到设置 `canonical_app_id` 的公开 manifest 字段。当前 Plugin Creator 更新工具也没有该字段。

这些证据将问题定位到宿主插件记录的主应用关联与按钮选择。不能再通过修改 MCP 的 `open_settings` 元数据或反复上传相同绑定来宣称修复；也不能伪造未公开的字段或直接调用浏览器内部写接口。

## 0.5.3 已验证的直接入口

原插件 `interface.websiteURL` 指向已验证的 ChatGPT 内嵌面板路由，绑定的应用和原插件身份保持不变。实际从原插件详情点击“网站”后，在同一个浏览器标签内进入已授权的邮箱面板，不需要聊天指令、授权页或另一个浏览器窗口。未增加服务器网页，也未改写主应用关联。

这是宿主支持的普通链接入口，标签仍为“网站”；顶部主按钮仍为“在聊天中试用”。它解决原插件页面到面板的直接导航，但不能宣称已经修复顶部按钮。此次仅修改插件展示元数据，MCP 工具、资源及认证均未变化，沿用已验证的服务器 0.5.2，不需要重部署。
